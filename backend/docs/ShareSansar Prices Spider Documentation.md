# ShareSansar Prices Spider

## Overview

`ShareSansarPricesSpider` is a Scrapy spider that collects daily stock-price information from ShareSansar. It supports both the current day's market data and a configurable number of historical days.

The spider also integrates with the application's `Company` model and restricts extraction to symbols contained in the application's watchlist.

## Spider Configuration

- **Spider name:** `sharesansar_prices`
- **Start URL:** `https://www.sharesansar.com/today-share-price`
- **Framework:** Scrapy
- **Robots.txt:** Enabled
- **Download delay:** 2 seconds
- **User-Agent:** `StockAppAssignmentCrawler/1.0`

These settings help control request frequency and crawler behavior.

## Watchlist Integration

Before processing prices, the spider retrieves company symbols from the application's database through the `Company` model.

The database operation is exposed asynchronously using `sync_to_async`, allowing it to be used from the spider's asynchronous `parse()` method.

Only stock symbols that exist in the application's watchlist are processed. This prevents unnecessary extraction and storage of companies that are not relevant to the application.

## Current-Day Price Collection

When the spider starts, it extracts the current date from the ShareSansar page and processes the table using `extract_rows()`.

This provides the latest available market data without requiring an additional historical request.

## Historical Price Collection

The `days_back` argument controls the historical data range.

For example:

```bash
scrapy crawl sharesansar_prices -a days_back=30
```

With `days_back=30`, the spider collects today's data plus the previous 29 days, resulting in 30 days of data in total.

Historical data is requested through ShareSansar's AJAX endpoint using a POST request. The request includes the CSRF token, target date, and `all_sec` sector value.

## Historical Response Handling

`parse_historical()` validates the returned response before attempting extraction. It checks for expected table-related HTML and logs a warning when valid table data is not found.

Once validated, the response is converted into a Scrapy selector and passed to `extract_rows()`.

## Data Extraction

The `extract_rows()` method processes each table row and expects at least 14 cells. Rows that do not contain sufficient data are skipped.

The stock symbol is extracted from the second cell and normalized before being checked against the application's watchlist.

The spider also includes helper functions for cleaning numeric values and converting them into appropriate Python numeric types:

- `Decimal` for price and monetary values
- `int` for volume
- Invalid decimal values are safely converted to `Decimal("0")`
- Invalid integer values are converted to `0`

## Output Schema

For each matching company, the spider produces:

| Field | Description |
|---|---|
| `symbol` | Stock ticker symbol |
| `date` | Trading date |
| `open` | Opening price |
| `high` | Highest traded price |
| `low` | Lowest traded price |
| `close` | Closing price |
| `volume` | Number of traded shares |
| `turnover` | Total trading turnover |

These fields are generated by `extract_rows()`.

## Data Flow

The overall processing flow is:

**ShareSansar → Current-day price page → Extract today's prices → Generate historical dates → AJAX requests → Validate responses → Extract table rows → Filter by watchlist → Normalize numeric data → Yield price records**

## Purpose

This spider is suitable for maintaining market-price data for a stock application, including:

- Daily stock-price updates
- Historical price storage
- Watchlist-specific market data
- OHLC analysis
- Volume and turnover tracking
- Charting and technical analysis
- Financial dashboards
